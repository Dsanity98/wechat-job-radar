# 职聚 · 项目状态

目标用户 / 使用场景 / 核心问题：
- 求职者（应届生找校招、在校生找实习、职场人找社招）在多个招聘平台之间来回切换，难以及时发现和比较岗位。

期望结果 / 本轮范围及理由：
- 一个聚合三类岗位的小程序：浏览、搜索、筛选、查看详情、收藏。
- 本轮范围：三 Tab 岗位列表（全部/校招/实习/社招）、关键词搜索、城市与方向筛选、岗位详情、本地收藏。
- 未纳入：登录、多人同步、简历投递、消息推送、后台管理；收藏本轮为本地保存，不做跨设备同步。

核心流程 / 业务规则 / 产品验收条件：
- 首页默认加载最新岗位；切换类型、关键词、城市、方向即时过滤。
- 点击岗位进入详情，可查看职责、要求、官网链接并收藏。
- 收藏页按收藏时间倒序展示，可再次进入详情或取消收藏。
- 演示数据必须明确标记；云端模式缺失配置时给出可操作提示，不静默回退到演示数据。

事实与关键假设：
- 事实：主流中文招聘平台没有面向个人的免费公开实时接口；jobsearchradar 提供定时更新的开放快照；字节跳动、蔚来等官方招聘门户存在公开可读的匿名 JSON 接口。
- 假设：求职者首先需要「发现并筛选岗位」，投递行为保留在原文链接完成。

用户选择的后端模式及依据：
- 微信云开发：用于托管公开岗位数据与云函数，解决小程序域名白名单和后续接入第三方源的服务端代理问题。

架构 / 技术栈 / 视觉方向：
- 原生 WXML/WXSS/JavaScript；`services/jobs.js` 隔离数据访问，支持 demo 与 cloud 两种数据源。
- 云函数 `syncjobs` 每天定时拉取官方门户岗位并写入 `jobs` 集合，`importJobs` 用于批量回填。
- 视觉方向：克制、清晰的效率工具风格，主色蓝 `#2459d3`，白底卡片 16rpx 圆角，校招/实习/社招分别以蓝/绿/琥珀区分。

云接入目标 / 授权范围 / 阶段（仅 cloud）：
- 目标：用户指定的开发环境；授权范围：创建集合、部署 `syncjobs`/`importJobs` 并联调（环境 ID 已取得，`syncjobs` 已部署并联调通过）。
